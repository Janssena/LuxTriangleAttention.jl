Layers

LuxTriangleAttention.TriangleAttention — Type
TriangleAttention(chn_in, head_dim, num_heads; is_starting=true, kwargs...)

Implementation of Triangle Attention (AlphaFold2 Algorithms 13 & 14). Updates the pair representation by performing axial attention with a triangle bias. Per head $h$, AlphaFold2 Algorithm 13 (starting node) is

\[\begin{aligned} z_{ij} &\leftarrow \mathrm{LayerNorm}(z_{ij}) \\ q^h_{ij},\, k^h_{ij},\, v^h_{ij} &= \mathrm{LinearNoBias}(z_{ij}) \qquad b^h_{ij} = \mathrm{LinearNoBias}(z_{ij}) \qquad g^h_{ij} = \mathrm{sigmoid}\big(\mathrm{Linear}(z_{ij})\big) \\ a^h_{ijk} &= \mathrm{softmax}_k\Big(\tfrac{1}{\sqrt{c}}\, {q^h_{ij}}^{\top} k^h_{ik} + b^h_{jk}\Big) \\ o^h_{ij} &= g^h_{ij} \odot \sum_k a^h_{ijk}\, v^h_{ik} \\ \tilde{z}_{ij} &= \mathrm{Linear}\big(\mathrm{concat}_h(o^h_{ij})\big) \end{aligned}\]

and AlphaFold2 Algorithm 14 (ending node) uses $k^h_{kj}$, $b^h_{ki}$ and $v^h_{kj}$ in place of $k^h_{ik}$, $b^h_{jk}$ and $v^h_{ik}$. $c$ is head_dim.

Arguments

  • chn_in: Input channels.
  • head_dim: Dimension of each attention head.
  • num_heads: Number of attention heads.

Keyword Arguments

  • is_starting: If true, performs "Starting Node" attention (AlphaFold2 Algorithm 13). If false, performs "Ending Node" attention (AlphaFold2 Algorithm 14).
  • use_bias: Boolean or NamedTuple for internal layer biases.
  • layernorm_eps: Epsilon for LayerNorm.
  • rank: The rank (ndims) of the input.
  • Remaining kwargs are forwarded to the inner Attention — notably chunk_size, which bounds the O(N³·H) attention-score footprint by attending over slices of the batch axis.

Inputs

  • x: Input tensor with shape [C, Ni, Nj, B].
  • mask: Optional mask with shape [Ni, Nj, B].

The triangle bias is NOT a user-supplied input: linear projects it from x itself (b = Linear(x_norm), shape [H, Ni, Nj, B]). It is then handed to the inner Attention with bias_layout=:qk, which calls prep_bias on it internally.

Returns

  • y: Output tensor with shape [C, Ni, Nj, B].
  • st: Updated state.

Example

using Lux, LuxTriangleAttention, Random

model = TriangleAttention(64, 32, 4; is_starting=true)
ps, st = Lux.setup(Random.default_rng(), model)

x = randn(Float32, 64, 32, 32, 1)
mask = rand(Bool, 32, 32, 1) # Pairwise boolean mask

# Pass inputs via NamedTuple; the bias is computed internally, not supplied here
y, st = model((; x, mask), ps, st)

LuxTriangleAttention.TriangleMultiplication — Type
TriangleMultiplication(chn_in, chn_hidden; is_outgoing=true, kwargs...)

Implementation of Triangle Multiplication (AlphaFold2 Algorithms 11 & 12). Updates the pair representation by combining edges sharing a common node. AlphaFold2 Algorithm 11 (outgoing edges) is

\[\begin{aligned} z_{ij} &\leftarrow \mathrm{LayerNorm}(z_{ij}) \\ a_{ij},\, b_{ij} &= \mathrm{sigmoid}\big(\mathrm{Linear}(z_{ij})\big) \odot \mathrm{Linear}(z_{ij}) \\ g_{ij} &= \mathrm{sigmoid}\big(\mathrm{Linear}(z_{ij})\big) \\ \tilde{z}_{ij} &= g_{ij} \odot \mathrm{Linear}\Big(\mathrm{LayerNorm}\big(\textstyle\sum_k a_{ik} \odot b_{jk}\big)\Big) \end{aligned}\]

and AlphaFold2 Algorithm 12 (incoming edges) sums $a_{ki} \odot b_{kj}$ instead.

Arguments

  • chn_in: Input channels.
  • chn_hidden: Hidden channels for internal projections.

Keyword Arguments

  • is_outgoing: If true, performs "Outgoing" multiplication (AlphaFold2 Algorithm 11). If false, performs "Incoming" multiplication (AlphaFold2 Algorithm 12).
  • layernorm_eps: Epsilon for LayerNorm.
  • rank: The rank (ndims) of the input.
  • kwargs...: Passed to TriMulCore.

Inputs

  • x: Input tensor with shape [C, N, N, B].
  • mask: Optional mask with shape [N, N, B].

Returns

  • y: Output tensor with shape [C, N, N, B].
  • st: Updated state.

LuxTriangleAttention.Attention — Type
Attention(chn_q, chn_k, chn_v, head_dim, num_heads; use_bias=false, fuse_qkv=true,
    use_gate=static(true), bias_layout=:kq, chunk_size=nothing, use_kernel=static(false))
Attention(chn_q, chn_kv, head_dim, num_heads; kwargs...)
Attention(chn_in, head_dim, num_heads; kwargs...)

Multi-head attention layer. Supports self-attention, cross-attention, and gated attention.

Arguments

  • chn_q: Channels for the query input.
  • chn_k: Channels for the key input.
  • chn_v: Channels for the value input.
  • head_dim: Dimension of each attention head.
  • num_heads: Number of attention heads.

Keyword Arguments

  • use_bias: A NamedTuple or Bool specifying which internal layers should use bias. Defaults to false.

  • fuse_qkv: If true, fuses the Q, K, and V projections into a single dense layer (where possible).

  • use_gate: If true (or static(true)), applies a sigmoid gating to the attention output.

  • use_kernel: If true (or static(true)), routes attention through the default (or user-defined) fused kernel (see use_kernel! / tune_flash_kernel!) instead of Lux.scaled_dot_product_attention. Defaults to false.

    This only takes effect on GPU arrays. On CPU, SDPA always runs the ordinary softmax regardless of this flag. A model built with use_kernel=true still runs (correctly, just without the speedup); the flag applies the moment the arrays are actually on a device with a usable kernel selected.

    Mutually exclusive with chunk_size: a fused kernel tiles the keys internally, so there is nothing left for chunk_size to slice, and combining the two raises AssertionError at construction.

  • bias_layout: A Symbol (either :qk or :kq) indicating how the attention bias tensor should be prepared internally. Defaults to :kq.

    • :qk: Used in TriangleAttention. Expects a bias of shape [H, Ni, Nj, B], which is permuted to [Ni, Nj, H, 1, B] to match the Julia Lux 3rd-dimension attention default. Since the input is also permuted in TriangleAttention, no additional transpose of the bias is required.
    • :kq: Used in pair-bias implementations (e.g., MSA or general pair representations). Expects a bias of shape [H, Nq, Nk, B], which is permuted/transposed to [Nk, Nq, H, 1, B] to correct for the difference between Julia Lux's 3rd-dimension attention and Python's 4th-dimension attention when working with inputs of shape [C, N, S, B] (vs Python's [B, S, N, C]).

  • chunk_size: If given, run the attention in slices of chunk_size along dim 4 of the prepared q/k/v instead of all at once. Defaults to nothing (no chunking). The result is unchanged but the live score tensor shrinks from [Nq, Nk, H, dim4, …] to chunk_size entries at a time.

    Attention runs over token_dim=3, so dim 4 is the first axis it batches over and for a pair input [C, Ni, Nj, B] that is Nj, a token axis, not the sample batch. Chunking therefore helps at B == 1, whose scores are O(N³·H), ~1 GiB per op at N=400. For a 3-D input [C, N, B] dim 4 is the sample batch, so chunk_size is a no-op at B == 1. Equivalent to chunk_size_tri_attn in the openfold/boltz references.

    Float16. The chunked paths are Float16-safe, eagerly on the CPU and rolled under Reactant (a chunk runs in Float32 there, since the compiler may move the 1/√d scale past Q·Kᵀ and overflow the logits). The plain path (chunk_size=nothing, use_kernel=false) is LuxLib's SDPA, which is not Float16-safe under Reactant and materialises every score; it is for reference and tests, not production. Use chunk_size or use_kernel.

    Under Reactant.@compile the Reactant extension rolls the chunk loop into a stablehlo.while; the plain Julia loop here would be unrolled and scheduled concurrently, preventing any reductions in memory usage.

    Verify the REVERSE before relying on a specific chunk size

    Differentiating the rolled loop hits an unfixed Reactant/Enzyme defect for some configurations: the chunk write lowers to a dynamic_update_slice whose update has one rank too many (update rank does not match operand rank: 6 vs 5). The FORWARD is unaffected.

    No rule predicts it. Measured on a bare Attention (chn=32, headdim=8, numheads=4), the same at every N tried (8, 12, 16, 20, 24):

    nchunks23456
    reverse✗✗✓✗✓

    A specific nchunks might work or fail depending on the surrounding layer (e.g. a PairFormer block featuring TriangleAttention layers). Eliminated as causes: the chunked axis's position and rank, the loop body, the number of carried buffers, mask, bias, num_heads, and absolute N.

Inputs

  • x: Input tensor(s). Can be an AbstractArray for self-attention, or a Tuple of arrays for cross-attention (e.g., (q, kv) or (q, k, v)). Expected shape: [C, N, (N or S, ) B].
  • bias: Optional attention bias tensor. Expected shape: [num_heads, Nq, Nk, B]. Must have the correct shape for broadcasting. See prep_bias.
  • mask: Optional attention mask. Expected shape: [Nq, (S, ) B] or [Ni, Nj, B]. Masks are automatically reshaped to the internal 4D/5D attention score format.

Returns

  • y: The output tensor. Shape matches q (typically [chn_q, N, (N or S, ) B]).
  • st: Updated state.

Example

using Lux, LuxTriangleAttention, Random

# Self-attention with mask
model = Attention(64, 32, 4)
ps, st = Lux.setup(Random.default_rng(), model)

x = randn(Float32, 64, 32, 1)
mask = rand(Bool, 32, 1)

# Pass inputs as a NamedTuple
y, st = model((; x, mask), ps, st)

Note on Dimensions

This implementation performs attention over the 3rd dimension (token_dim=3). This is different from most Python references (e.g., Boltz-2, AlphaFold2 and 3) which typically attend over the 4th dimension.

  • TriangleAttention (bias_layout=:qk): In TriangleAttention, we pass a bias of shape [H, Ni, Nj, B] which is permuted internally to enable the model to attend to the 3rd dimension in q, k, v (representing Nj). The input is of size [C, Ni, Nj, B]. Permuting the input also permutes the resulting bias correctly, meaning no additional changes to the bias orientation are needed.
  • Generic pair-bias attention (bias_layout=:kq), matching the layout of the AttentionPairBias module in the AlphaFold3/Boltz Python references. For generic pair bias attention, the input is of shape [C, N, S, B] (where S is the pair/MSA dimension), and we attend over the N dimension. In Python, the equivalent shape is [B, S, N, C]. While the Julia input layout works naturally with Lux's 3rd-dimension attention default, the bias tensor of shape [H, Nq, Nk, B] must be permuted to [Nk, Nq, H, 1, B] to correct for the transposition. This is handled by the :kq layout.

LuxTriangleAttention.ChannelsLast — Type
ChannelsLast(layer)

layer applied to CHANNELS-LAST data: input [..., in], output [..., out], where Lux's own convention is channels-first ([in, ...]). Supported: Lux.Dense, Lux.LayerNorm (normalising the channel axis only) and GatedLinearUnit/SwiGLU. Any other layer throws.

The parameters and states are the wrapped layer's own, unnested (an AbstractLuxWrapperLayer), so ChannelsLast(Dense(chn => hidden)) has exactly the parameter tree of Dense(chn => hidden): the same initialisation, the same weight loading.

Why

A Dense on channels-last data computes x · Wᵀ instead of W · x, and the result is channels-last too. Inside a layer this is often cheaper:

  • a channels-last [N², H] projection IS the per-channel [N, N] "planes" layout a batched contraction over tokens wants (e.g. TriMulCore), so no permutedims is needed before it;
  • under Reactant → jax-mps, channels-last chains lower to row-major dot_generals, which jax-mps runs 1.1–1.9× faster (docs/FEATUREjaxmpsdot_orientation.md §3b).

Whether it pays off is a per-layer measurement, not a rule: see test/scratch/layout_harness.jl.

Entering and leaving the layout

A 2-D input may be a lazy transpose of channels-first data: ChannelsLast(d)(transpose(x), ps, st) computes xᵀ · Wᵀ directly, with no copy. The way back is one permutedims at the end of the layer.

Example

d = ChannelsLast(Lux.Dense(128 => 512))
ps, st = Lux.setup(rng, d)                 # same as for Lux.Dense(128 => 512)
y, _ = d(randn(Float32, 64, 64, 128), ps, st)   # [64, 64, 512]

LuxTriangleAttention.prep_bias — Function
prep_bias(bias, x, bias_layout)

Utility to prepare and reshape the attention bias tensor based on the input shape and the specified bias_layout.

Arguments

  • bias: The raw bias tensor (or nothing).
  • x: The input tensor to the attention layer.
  • bias_layout: A StaticSymbol specifying the permutation strategy (:qk or :kq).

Permutation Strategies

  • :qk (Symmetric/Triangle Attention): For an input of shape [C, Ni, Nj, B] and bias of shape [H, Ni, Nj, B], permutes the bias to [Ni, Nj, H, 1, B] (preserving the spatial dimensions Ni and Nj).
  • :kq (Asymmetric/Pair Attention): For an input of shape [C, N, S, B] and bias of shape [H, Nq, Nk, B], permutes the bias to [Nk, Nq, H, 1, B] (transposing spatial dimensions to correct for Julia's 3rd-dimension attention vs Python's 4th-dimension attention).

Notes on Dimensions

Python packages (such as AlphaFold and Boltz) typically perform attention over the 4th dimension (using [B, S, N, C]). Julia's Lux default is to attend over the 3rd dimension ([C, N, S, B]). The bias_layout determines how the bias tensor is adjusted to maintain parity with the Python attention mechanisms under these different dimension conventions.

Normalisation

LuxTriangleAttention.StableLayerNorm — Type
StableLayerNorm(shape, activation=identity; epsilon=1f-5, dims=Colon(), affine=True(), kwargs...)
StableLayerNorm(layer)    # a Lux.LayerNorm, or one frozen with `Lux.Experimental.freeze`

A Lux.LayerNorm whose statistics are always accumulated in Float32 when the data is 16-bit.

For Float32 and Float64 (and any non-16-bit input, traced or not) it IS the wrapped Lux.LayerNorm: the call is layer(x, ps, st), so whatever Lux and LuxLib dispatch on for the array type — today a generic AbstractArray method that traced Reactant arrays flow through, and any AnyTracedRArray method a later Lux adds — is used unchanged, and the result is bitwise the layer's own.

For Float16 and BFloat16 it computes the mean and variance in Float32 (layernorm_f32stats) and returns the result in the input's type, with the layer's own scale, bias, activation, dims and epsilon. Lux.LayerNorm accumulates in the input type, where the sum of squares behind the variance overflows Float16 at |x| ≈ 20 over a few hundred channels (σ² ≈ 2e6 on AlphaFold2's pair activations is not representable): finite but 85–99% wrong output on pair activations with σ ≈ 60 over 32 channels.

The parameters and state are the wrapped layer's own, unnested (an AbstractLuxWrapperLayer), so StableLayerNorm(shape) has exactly the parameter tree of Lux.LayerNorm(shape): the same initialisation, the same weight loading. ChannelsLast supports it too (for the unfrozen layer).

The wrapped layer may be a Lux.LayerNorm frozen with Lux.Experimental.freeze (that is what LayerNormNoBias builds): its frozen parameters live in the state, and the Float32 path reads them from there.

LuxTriangleAttention.layernorm_f32stats — Function
layernorm_f32stats(x, scale, bias, activation, dims, epsilon, ::Type{T})

Normalise x over dims with the mean and variance accumulated in Float32, in ONE pass (σ² = E[x²] − μ²), and return the result in T.

For 16-bit inputs the statistics cannot stay in the input type: the sum of squares over a few hundred channels overflows Float16 at |x| ≈ 20, and σ² itself (≈2e6 on AlphaFold2's pair activations) is not representable. One pass is safe here although it is not for Float32 inputs: for 16-bit data accumulated in Float32 its cancellation error stays below the input's own rounding until |μ|/σ ≈ 2¹⁴. Only μ and 1/√(σ²+ε) are converted back, so a 16-bit x is normalised in T without a Float32 copy; a Float32 x (a contraction computed wide) is normalised in Float32 and then converted. epsilon is used in Float32, so it may be far below T's range. scale/bias (or nothing) must already be broadcast-compatible with x; they are narrowed to T if wider.

LuxTriangleAttention.mask_value — Function
mask_value(T::Type) -> T
mask_value(x::AbstractArray) -> eltype

The value to put where attention is masked: -floatmax(T) / 2, FINITE in every precision. A masked logit written as -Inf (what typemin is for a float, and what LuxLib fills in), or as a large constant that overflows T, turns a row with no live key into -Inf - (-Inf) = NaN; OpenFold's and Boltz2's 1e9 * (mask - 1) is finite in Float32 but IS -Inf in Float16 (Float16(-1e9) == -Inf), which is how a fully padded window gave NaN there. Use it by SELECTING, not adding:

logits = ifelse.(keep, logits, mask_value(T))

A select needs only that the value is finite, so it holds in any precision, and a row where every logit is mask_value is a uniform softmax (the behaviour of a fully masked row everywhere in this package, see SDPA). As an additive bias it still fits T for logits of magnitude below floatmax(T) / 2 (about 3.3e4 in Float16); a select is the safe form. exp(mask_value(T) - m) is exactly 0 for any row maximum m a model can produce, so masked keys get no weight in a row that has a live one.

BFloat16 (Core.BFloat16, and Reactant's) has Float32's exponent range and gets Float32's value.

LuxTriangleAttention.fold_k — Function
fold_k(L::Integer) -> Int

The scale exponent for a contraction of length up to L: the smallest k with 4ᵏ ≥ L. Folding 2⁻ᵏ into each of the two projections divides the contraction by 4ᵏ, so it sums roughly a mean whose size no longer grows with L. A k larger than needed only leaves values smaller, which Float16 represents at full relative precision down to 6e-5, so L is a BOUND (the longest contraction the parameters must serve), not the length of any particular input.

source
LuxTriangleAttention.fold_trimul — Function
fold_trimul(ps, st, k) -> (ps, st)

Prepare a TriangleMultiplication's parameters for the Folded path: scale the VALUE projections of a and b (never the gates) by 2⁻ᵏ and record fold_k = k in the core's state. Apply it to the Float32 parameters, before casting to 16 bits (the scaling is a power of two, so it is exact either way, but subnormal weights would round). Use fold_k(L) for the longest sequence the parameters must serve.

The contraction then sums Σ a·b / 4ᵏ, and the output LayerNorm (scale-invariant, with ε scaled by 16⁻ᵏ in the layer) makes the layer's result exactly the unscaled one.

Attention kernels

LuxTriangleAttention.SDPA — Type
SDPA

The attention op: SDPA()(q, k, v, mask, bias) -> (o, lse). q, k, v are [hd, H, Nq, Nj, B] (or a plain [hd, H, N, B] sequence), mask a KEEP mask and bias the pair bias, both optional. Host arrays run _sdpa_default (lse = nothing); device arrays the selected kernel — use_kernel!(SDPA, :flash_mma).

A fully masked key set

If every key of an (outer index, batch) slice is masked, its queries attend UNIFORMLY, as in OpenFold and Boltz2 (whose finite 1e9·(mask - 1) bias makes all logits equal): o is the mean of v over the n keys, never NaN. The reverse gives dV = dO / n to every key and nothing to q, k or bias (the logits were replaced). Every path follows it: _sdpa_default, the rolled chunk path and both kernels, which write lse = -Inf for such a query as the marker their backward reads. Only a WHOLE slice is dead this way; a single query made all -Inf by its own bias is not.

LuxTriangleAttention.tune_flash_mma! — Function
tune_flash_mma!(lengths=tune_lengths(); dim, T=Float32, force=false) -> variants

tune!(FlashMMA(), lengths; dim, T, force): tune, compile and register the matrix-unit kernel :flash_mma at each length in lengths; select it with use_kernel!(:flash_mma). A call of any length runs the closest tuned one; an eager call with none tunes tune_lengths lazily, a traced one refuses. dim must be a multiple of 8, and of the device's contraction width (8 on Metal, 16 on NVIDIA) to run on the matrix units; other multiples of 8 run :default. Where the device computes T at another type (Float32 at Float16 on CUDA, see mma_compute_type) that type is tuned; where it has none, a call runs :default and this returns without tuning.

LuxTriangleAttention.calibrate! — Function
calibrate!(kernel, T=Float32; dim, n, force=false, probe_heads=4, persist=true)
    -> Dict(stage => Dict(point => seconds))

Measure every stage of a built-in kernel on this device at sequence length n: the admissible points of its tune_grid, searched (search) and each measured — built, admitted by its pipeline, verified, timed on a triangle probe of n queries (nouter = n, capped for memory) and probe_heads head slices. Persisted (calibration_path), so a later call is a file read; force=true re-measures.

Keyed by (kernel, device, dim, T, n): T is the STORAGE type, part of the key because it changes which configurations are legal (the staged tiles are held in storage precision), not merely how fast they are. A stage with no finite point is an error — there is then no kernel to run.

LuxTriangleAttention.tune_lengths — Function
tune_lengths() -> Vector{Int}

The sequence lengths the built-in kernels are tuned for when no length is given — by tune_flash_kernel! / tune_flash_mma! and by the first device call that finds no variant. Default [256, 512], which suits most binder-design work; set it per project with set_tune_lengths! (e.g. [256, 512, 768, 1024] for larger proteins).

LuxTriangleAttention.resolve_defaults — Function
resolve_defaults(defaults, keys)

Utility to resolve default values for a set of keys. This is used to handle nested configuration for bias and other layer options.

Arguments

  • keys: A NTuple{N, Symbol} of keys to resolve defaults for.

Returns

  • A NamedTuple containing the resolved values for all requested keys.
